エラーログを吐き出して華々しくクラッシュするなら、まだ救いはあります。しかし、Pythonの `asyncio` を用いた非同期環境において最も恐ろしいのは、**何も言わずにただプロセスが沈黙していく現象**です。

CPU使用率は跳ね上がり、メモリは少しずつ膨張していく。しかし、リクエストはタイムアウトを返し続け、システム全体が麻痺状態に陥る。徹夜でコードベースの海を彷徨い、数日かけて原因を突き詰めた結果、見つかったのは「非同期関数内での不用意な同期I/O呼び出し」や「例外発生時に未解放となった `asyncio.Lock`」だった――。

エンジニアの命とも言える「有限な時間」が、このような不条理なデバッグ地獄に溶かされていくのを、我々は見過ごすわけにはい đi ません。

本記事では、この泥沼のハングアップを水際で防ぎ、システムの命脈を保つために私たちが設計した防衛アーキテクチャ「**AsyncGuard**」の内部構造と、そこに至るまでの技術的な意思決定、そして開発の苦労話について深く掘り下げます。

## 1. プロダクションで響く「静かなる沈黙」のシグネチャ

`asyncio` は、シングルスレッド上で協調的マルチタスク（Cooperative Multitasking）を行うモデルです。これはつまり、**どこか1つのコルーチンが制御をイベントループに返さなければ（`await` しなければ）、他のすべてのタスクが道連れにして停止する**という脆弱性を孕んでいることを意味します。

## 2. 魔法の杖は存在しない。必要なのは「多層防衛」

この問題に対処する際、私たちは「あらゆるバグを自動で修正するAI」のような非現実的なアプローチを直ちに棄却しました。

シニアエンジニアにとって真に必要なのは、問題の発生をコンパイル時（CI/CD時）に構造的に警告し、それでもすり抜けた異常をランタイムで検知して被害を最小化する**「現実的なセーフティネット」**です。

そこで私たちは、システムアーキテクチャを「静的解析（予防）」と「ランタイム監視（フェイルセーフ）」の2つのレイヤーに分離しました。

## 3. 防衛線1: ASTによる静的解析パイプライン

第一の防衛線は、抽象構文木（AST: Abstract Syntax Tree）を用いた静的解析です。Python標準の `ast` モジュールを利用し、コミット前やCIパイプライン上でコードの構造そのものをスキャンするアプローチを採用しました。

```python
import ast
import sys
from typing import List, Tuple

class AsyncBlockingDetector(ast.NodeVisitor):
    """
    async def の中でブロッキング処理（time.sleep, requests等）が
    呼び出されていないかを静的に検出するASTビジター
    """
    BLOCKED_MODULES = {"time": {"sleep"}, "requests": {"get", "post", "put", "delete"}, "urllib": {"urlopen"}}

    def __init__(self, filename: str):
        self.filename = filename
        self.issues: List[Tuple[int, str]] = []
        self._in_async_def = False

    def visit_AsyncFunctionDef(self, node: ast.AsyncFunctionDef):
        old_in_async = self._in_async_def
        self._in_async_def = True
        self.generic_visit(node)
        self._in_async_def = old_in_async

    def visit_Call(self, node: ast.Call):
        if self._in_async_def:
            if isinstance(node.func, ast.Attribute) and isinstance(node.func.value, ast.Name):
                mod_name = node.func.value.id
                func_name = node.func.attr
                if mod_name in self.BLOCKED_MODULES and func_name in self.BLOCKED_MODULES[mod_name]:
                    self.issues.append((
                        node.lineno,
                        f"CRITICAL: Blocking call '{mod_name}.{func_name}' found inside async function."
                    ))
        self.generic_visit(node)
```

## 4. 防衛線2: ランタイムトレーサーと安全なフォールバック機構

イベントループの応答性をバックグラウンドで常時監視し、異常検知時にサーキットブレーカーを発動させる「ランタイムガード」を実装しました。

```python
import asyncio
import logging
from typing import Callable, Any

logger = logging.getLogger("AsyncGuard.Runtime")

class AsyncGuardRuntime:
    def __init__(self, check_interval: float = 1.0, stall_threshold: float = 3.0):
        self.check_interval = check_interval
        self.stall_threshold = stall_threshold
        self._is_monitoring = False

    async def _monitor_loop(self, loop: asyncio.AbstractEventLoop):
        while self._is_monitoring:
            start_time = loop.time()
            await asyncio.sleep(self.check_interval)
            elapsed = loop.time() - start_time
            
            drift = elapsed - self.check_interval
            if drift > self.stall_threshold:
                logger.error(
                    f"[AsyncGuard] Event loop stall detected! "
                    f"Delayed by {drift:.2f}s (Threshold: {self.stall_threshold}s)"
                )

async def guarded_execution_safe(
    coro_func: Callable[..., Any], 
    *args, 
    timeout: float = 5.0, 
    fallback_value: Any = None,
    **kwargs
) -> Any:
    try:
        return await asyncio.wait_for(coro_func(*args, **kwargs), timeout=timeout)
    except asyncio.TimeoutError:
        logger.warning(
            f"[AsyncGuard] Execution of {coro_func.__name__} timed out after {timeout}s. "
            f"Triggering safe fallback."
        )
        return fallback_value
    except asyncio.CancelledError:
        logger.info(f"[AsyncGuard] Execution explicitly cancelled.")
        raise
```

私たちは日々コードと向き合っていますが、その裏側にあるのは極めて泥臭い現実です。

本番稼働中のPython製非同期マイクロサービスで突如発生する `RuntimeError` や `StaleDataError`（非同期レースコンディション）。深夜3時に鳴り響くアラートに叩き起こされ、霞む目でログを追うSREやバックエンドエンジニアたち。

近年、「AIがすべてのバグを完璧に、全自動で直してくれる」という幻想が蔓延していますが、現場のエンジニアなら知っているはずです。世の中のツールは、往々にしてインデントを崩し、デッドロックを引き起こし、サービスを全停止させるリスクを孕んでいるということを。

この記事では、私たちが開発した「ローカルLLM駆動型・リアルタイム例外スタックトレース自動パッチ適用エンジン（AutoFix-AST-Pipeline）」のアーキテクチャと、その裏側にある実機（RTX 4090 / 24GB VRAM）における泥臭い失敗、4重のガードレール、そして開発者の時間を奪還するための戦いの軌跡を共有します。

## 課題の背景：なぜローカルLLMなのか？

機密性の高いプロダクションコードやスタックトレースを、外部のクラウドAPIに無邪気に送信することはセキュリティポリシー上許容されません。情報の秘匿性は命綱であるため、ローカル環境で完結するLLMの採用は絶対条件でした。

しかし、ローカル環境には「物理法則」という絶対的な制約があります。標準的な推論ノードである RTX 4090 (24GB VRAM) の限られたリソース内で、高速かつ正確にコードのパッチを生成する必要がありました。モデルには、軽量でありながらコーディング能力に特化した `Qwen2.5-Coder-7B` を選定しました。

## 私たちが直面した「2つの地獄」

### 地獄 1：無限ハルシネーションとOOMクラッシュ
* **発生環境:** RTX 4090 (24GB VRAM) + Ollama (`qwen2.5-coder:7b-instruct-q4_K_M`)
* **何が起きたか:** 非同期ループ内で起きた10層超の深いスタックトレースをそのままプロンプトに流し込んだところ、コンテキスト長を速攻で超過しました。結果、暴走したLLMは存在しない外部ライブラリのパッチを生成し、OllamaデーモンがVRAMを食いつぶしてOOMでクラッシュしました。
* **対策:** スタックトレースを「直近3フレーム」のみに絞り込むプリプロセッサを強制実装し、`temperature=0.0` と厳格なJSON出力を課すことで、構造化されたASTの差分だけを出力させる設計へとシフトしました。

### 地獄 2：インデント崩れによるデータベース・デッドロック
* **発生環境:** FastAPI + SQLAlchemy（非同期セッション管理）
* **何が起きたか:** 楽観的ロックエラーに対し、LLMがリトライループを挿入した際、インデントを1文字誤りました。Pythonの構文としては成立してしまったため、トランザクションが永久に解放されず、コネクションプールが完全枯渇しました。
* **対策:** 関数単位の `ast.NodeTransformer` によるノード置換に限定し、適用の直前に `ast.parse()` と `mypy` による構文・型チェックのドライランを義務付けました。

## マジックはない。あるのは「4重のガードレール」だ

LLMの出力を信用しないために、バックエンド側に以下の多重防御（Validation Pipeline）を実装しています。

1. **JSONスキーマ検証:** 自由記述の出力や解説文を物理的にブロックする。
2. **Python構文チェック (`ast.parse`):** 構文エラーやインデント崩れのあるパッチは即座に破棄。
3. **危険な組み込み関数ブラックリスト:** `eval`, `exec`, `__import__`, `globals()` などの呼び出しを完全にブロックする。
4. **関数シグネチャの整合性検証:** 対象関数名や引数が勝手に書き換えられていないかをASTレベルで厳密に突合する。

## コアロジック実装：安全なAST解析とローカルLLM連携

以下に、例外キャプチャからAST安全検証、パッチ適用までのバックエンドコアロジックの一部を示します。

### 例外キャプチャ & ASTコンテキスト抽出 (`ast_extractor.py`)

```python
import ast
from typing import Tuple

class ASTContextExtractor:
    def __init__(self, source_code: str):
        self.source_code = source_code
        self.tree = ast.parse(source_code)

    def extract_node_around_line(self, target_line: int) -> Tuple[str, ast.AST]:
        target_node = None
        for node in ast.walk(self.tree):
            if isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)):
                if hasattr(node, 'lineno') and hasattr(node, 'end_lineno'):
                    if node.lineno <= target_line <= node.end_lineno:
                        target_node = node
                        break
        
        if not target_node:
            raise ValueError(f"Target line {target_line} is outside of any function scope.")

        unparsed_code = ast.unparse(target_node)
        return unparsed_code, target_node
```

### ローカルLLM推論 & 厳格なASTバリデーション (`patch_engine.py`)

```python
import httpx
import json
import ast
from typing import Optional, Dict, Any

class LocalLLMPatchEngine:
    def __init__(self, ollama_url: str = "http://localhost:11434/api/generate", model_name: str = "qwen2.5-coder:7b-instruct"):
        self.ollama_url = ollama_url
        self.model_name = model_name

    def validate_patch(self, original_code: str, fixed_snippet: str) -> bool:
        try:
            parsed_tree = ast.parse(fixed_snippet)
        except SyntaxError as e:
            return False

        for node in ast.walk(parsed_tree):
            if isinstance(node, ast.Call):
                if isinstance(node.func, ast.Name) and node.func.id in ['eval', 'exec', '__import__']:
                    return False

        return True
```

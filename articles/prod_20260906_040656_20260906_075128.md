# Docker-LeanOps: レガシー・コンテナ最適化＆脆弱性スキャンガードキット 実装ベストプラクティス

バックエンド・インフラの最適化は、限られたリソース（演算能力と人間の時間）を極限まで高めるための最重要課題です。

本プロジェクト「Docker-LeanOps」における全成果物を統合し、開発現場の明日からのパイプラインにそのまま組み込める**「実装のベストプラクティスまとめ」**をここに公開します。

物理法則を無視した精神論は排除し、三現主義（現場・現物・現実）に基づいた実戦的なコードと設定のみを提示します。

## 1. 現場の課題：「コードの価値」から「時間の価値」へ

開発現場において、肥大化したDockerイメージ（例: `python:latest`をベースにした2GB超のイメージ）のビルド・プッシュ・プルにかかるオーバーヘッドは、単なるストレージの無駄遣いではありません。

CI/CDパイプラインの待ち時間、Kubernetes環境でのPod起動遅延（`ImagePullBackOff`の頻発）、そして未知の脆弱性（CVE）指摘に伴う緊急パッチ適用の遅れなど、**「インフラとセキュリティのデバッグにエンジニアの時間が溶ける現象」**を引き起こします。

本キットが提供するのは「単なるDockerfileの書き方」ではなく、**「レガシーイメージの闇に囚われ、原因不明のレイヤー肥大化や脆弱性アラートの対応に追われる数日間のデバッグ時間」**を代替する実戦的なガードレールです。

## 2. 泥臭い失敗ログの開示とアーキテクチャの選定理由

### 失敗ケース1: 「とりあえず `pip install`」が引き起こすレイヤー肥大化とビルドキャッシュ崩壊
* **発生した状況**:
  ```dockerfile
  FROM python:3.11-slim
  COPY . /app
  RUN pip install -r /app/requirements.txt
  CMD ["python", "main.py"]
```
* **生じた問題**:
  ソースコード（`COPY . /app`）を `pip install` の前に実行してしまったため、一行コードを修正するたびに数分かかる重いC拡張モジュール（`numpy`, `cryptography` 等）のビルド・インストールが毎回走るようになりました。さらに、`build-essential` やヘッダファイルがプロダクションイメージ内に残留し、イメージサイズが **1.4GB** に膨れ上がりました。

### 失敗ケース2: マルチステージビルド導入時のありがちな罠（依存関係の持ち出し漏れ）
* **発生した状況**:
  ビルドステージで `poetry` を使って仮想環境を作り、プロダクションステージへコピーしようと試みました。
* **生じた問題**:
  一部のネイティブライブラリがシステム側の共有ライブラリをビルド時に必要としていましたが、軽量なプロダクションステージ側にそれらのランタイム共有ライブラリをコピーし忘れたため、コンテナ起動時に即死（CrashLoopBackOff）しました。

これらの失敗から、我々は**「マルチステージビルドの徹底」**と**「CI/CDパイプラインでの静的解析・脆弱性スキャンの強制」**をアーキテクチャの根幹に据える決定を下しました。

## 3. ローカル診断層：イメージレイヤー肥大化診断CLI（`leanops-cli`）

開発者が手元で「なぜイメージが重いのか」を定量的に診断するためのPython製CLIツールです。

### 実装コード: `analyzer.py` (v1.1.0)
```python
#!/usr/bin/env python3
"""
LeanOps CLI - Container Layer & Dependency Bloat Analyzer
実戦的なDockerイメージの肥大化要因検出スクリプト
"""

import subprocess
import sys
import json
import shutil

def run_docker_history(image_name: str) -> list[dict]:
    """docker history を JSON形式で安全に取得する"""
    if not shutil.which("docker"):
        print("Error: docker command not found in PATH.", file=sys.stderr)
        sys.exit(1)
        
    cmd = [
        "docker", "history", "--no-trunc", "--format", 
        '{"id": "{{.ID}}", "created_by": "{{.CreatedBy}}", "size": "{{.Size}}"}'
    ]
    cmd.append(image_name)
    
    try:
        result = subprocess.run(cmd, capture_output=True, text=True, check=True)
    except subprocess.CalledProcessError as e:
        print(f"Error executing docker history: {e.stderr}", file=sys.stderr)
        sys.exit(1)
        
    lines = result.stdout.strip().split("\n")
    history_data = []
    
    for line in lines:
        if not line:
            continue
        try:
            data = json.loads(line)
            history_data.append(data)
        except json.JSONDecodeError:
            continue
            
    return history_data

def diagnose_bloat(image_name: str):
    print(f"[*] Analyzing image: {image_name} ...\n")
    
    try:
        size_cmd = ["docker", "inspect", "--format={{.Size}}", image_name]
        res = subprocess.run(size_cmd, capture_output=True, text=True, check=True)
        total_bytes = int(res.stdout.strip().replace("'", ""))
        total_mb = total_bytes / (1024 * 1024)
        print(f"Total Image Size: {total_mb:.2f} MB")
    except Exception as e:
        print(f"Warning: Could not fetch total size: {e}")
        total_mb = 0

    history = run_docker_history(image_name)
    
    risk_patterns = [
        ("apt-get update", "APT cache might remain. Use '&& rm -rf /var/lib/apt/lists/*' in the same RUN layer."),
        ("pip install", "Ensure pip cache is disabled ('--no-cache-dir') to prevent bloating."),
        ("build-essential", "Build tools detected in final image. Consider using multi-stage builds."),
        ("npm install", "Node modules or cache may be unoptimized. Use 'npm ci --omit=dev'.")
    ]
    
    warnings = []
    for layer in history:
        created_by = layer.get("created_by", "")
        for pattern, advice in risk_patterns:
            if pattern in created_by:
                warnings.append((pattern, advice, created_by[:80]))

    print("\n--- Diagnostic Results ---")
    if warnings:
        print(f"[!] Found {len(warnings)} potential optimization points:")
        for idx, (pattern, advice, snippet) in enumerate(warnings, 1):
            print(f"  {idx}. Pattern: '{pattern}'")
            print(f"     Advice:  {advice}")
            print(f"     Layer:   {snippet}...")
    else:
        print("[+] No obvious anti-patterns detected in history strings.")

    if total_mb > 500:
        print(f"\n[!] WARNING: Image size ({total_mb:.2f} MB) exceeds the 500MB recommended threshold for microservices.")
    else:
        print(f"\n[+] Image size is within healthy limits.")

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("Usage: python analyzer.py <image_name:tag>")
        sys.exit(1)
    diagnose_bloat(sys.argv[1])
```

## 4. ビルド層：プロダクション仕様マルチステージビルド・テンプレート

C拡張モジュールのコンパイルに必要なビルドツールをビルドステージに閉じ込め、ランタイムステージには必要最小限の共有ライブラリと非特権ユーザーのみを残す堅牢な構成です。

### 実装コード: `Dockerfile`
```dockerfile
# syntax=docker/dockerfile:1
# ==========================================
# Stage 1: Builder
# ==========================================
FROM python:3.11-slim@sha256:d82365253fa28242f360563462fcfec80b484ea2d8f9d0e2d3122c3666b6183e AS builder

WORKDIR /app

RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    libpq-dev \
    && rm -rf /var/lib/apt/lists/*

ENV POETRY_HOME=/opt/poetry
RUN pip install --no-cache-dir poetry==1.7.1
ENV PATH="$POETRY_HOME/bin:$PATH"

COPY pyproject.toml poetry.lock ./
RUN poetry config virtualenvs.in-project true

RUN --mount=type=secret,id=pip_config \
    if [ -f /run/secrets/pip_config ]; then \
        export PIP_CONFIG_FILE=/run/secrets/pip_config; \
    fi && \
    poetry install --no-dev --no-interaction --no-ansi

COPY . /app

# ==========================================
# Stage 2: Production Runtime
# ==========================================
FROM python:3.11-slim@sha256:d82365253fa28242f360563462fcfec80b484ea2d8f9d0e2d3122c3666b6183e AS runtime

WORKDIR /app

RUN apt-get update && apt-get install -y --no-install-recommends \
    libpq5 \
    && rm -rf /var/lib/apt/lists/*

RUN groupadd -g 10001 leanops && \
    useradd -u 10001 -g leanops -m -s /bin/bash leanops

COPY --from=builder --chown=leanops:leanops /app/.venv /app/.venv
COPY --from=builder --chown=leanops:leanops . /app

USER leanops

ENV PATH="$POETRY_HOME/bin:$PATH"
ENV PYTHONUNBUFFERED=1

EXPOSE 8000

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## 5. CI/CDパイプライン層：Hadolint & Trivy 統合ガード

Hadolintによる構文チェックと、Trivyによる脆弱性スキャンを統合したGitHub Actionsワークフローです。

### 実装コード: `.github/workflows/leanops-ci.yml`
```yaml
name: Docker-LeanOps CI/CD Guard

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  lint-and-scan:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Lint Dockerfile with Hadolint
        uses: hadolint/hadolint-action@v3.1.0
        with:
          dockerfile: Dockerfile
          failure-threshold: error

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Build local image for scanning
        uses: docker/build-push-action@v5
        with:
          context: .
          load: true
          tags: leanops-app:test

      - name: Run Trivy Vulnerability Scanner
        uses: aquasecurity/trivy-action@0.16.0
        with:
          image-ref: 'leanops-app:test'
          format: 'table'
          exit-code: '1'
          severity: 'CRITICAL,HIGH'
          ignore-unfixed: true
```

## はじめに

近年、AI駆動開発（AI-Driven Development）の急速な普及により、日々のコーディングやアーキテクチャ設計においてLLM（大規模言語模型）を活用することが当たり前になりました。Anthropicが提供する「Claude Code」はその最先端を行くツールですが、多くのエンジニアが利用しているデフォルトの「planモード」について、私は現在**一切使用していません**。

本記事では、なぜplanモードを使わないのかという開発効率の観点に加え、AIエージェントの過剰な推論がもたらす計算リソースの消費、ひいては**地球環境負荷低減（Green Software Engineering）**の文脈から、リソース最適化された新しいAI開発のあり方を解説します。

---

## 1. なぜClaude Codeの「planモード」を使わないのか

Claude Codeにおけるplanモードは、コードベース全体をスキャンし、詳細な実装計画を立ててから実行に移る機能です。一見すると安全で理にかなっているように思えますが、実際の開発現場では以下のボトルネックが存在します。

1. **過剰なコンテキスト消費とレイテンシ**
   planフェーズにおいて、LLMは膨大なファイルを再読み込みし、人間にとって当たり前すぎるレベルのステップまで細かく言語化します。これによりトークン消費量が跳ね上がり、API応答の待ち時間（レイテンシ）が増大します。
2. **「動くプロトタイピング」の遅延**
   アジャイル開発や実験的なコーディングにおいて、過度に綿密な「計画」はかえって柔軟性を奪います。コードを書いて動作させ、フィードバックを得るサイクルのほうが、結果として高品質なシステムに早く到達します。
3. **プロンプトエンジニアリングによる直接制御の優位性**
   現在、私はあらかじめ構造化された指示（TOAIフレームワーク等を用いた精密なコンテキスト制御）を直接Claude Codeに投入し、planモードというブラックボックスな中間ステップをバイパスしています。これにより、無駄な推論コストをカットしつつ、意図通りのコード出力を一発で得ることが可能です。

---

## 2. AI駆動開発と地球環境負荷低減（グリーンIT）

LLMの学習および推論には、想像以上に膨大な電力と水資源が消費されています。データセンターの冷却やGPUの稼働によるCO2排出量は、IT業界全体としても無視できない規模に達しています。

ここで重要になるのが**「計算リソースの最適化（Compute Optimization）」**です。

- **無駄な推論の排除**：planモードのような「二度手間」の推論プロセスを省くことは、直接的にGPUの稼働時間を削減し、消費電力を抑えることにつながります。
- **軽量かつ高精度なプロンプト設計**：無駄なトークンをやり取りせず、最小限のコンテキストで最大の成果を出す開発手法は、経済的なコスト削減だけでなく、地球環境負荷低減への直接的な貢献（Green AI）となります。

私たちは「AIを使っているからエコである」という幻想から脱却し、**「いかに少ない計算リソースで、いかに効率よくAIを駆動させるか」**を意識する時代に来ています。

## 3. まとめ

Claude Codeのplanモードを卒業し、ダイレクトかつ効率的なAI駆動開発へ移行することで、開発スピードの加速と計算リソースの最適化を同時に達成できます。個々のエンジニアが環境意識を持ってAIとのインタラクションを見直すことこそが、持続可能なソフトウェア工学の第一歩です。

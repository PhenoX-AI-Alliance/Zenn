## 泥臭い失敗ログが教えてくれた「非同期処理の罠」

AIにすべてを完璧に直させるような甘い期待は、プロダクション環境への自殺ボタンに等しいものです。私たちがこのパイプラインを設計した背景には、実稼働環境での血の滲むような失敗の歴史があります。

ここで得た重要な教訓は、「単に `KeyError` を握り潰すだけでは意味がない」ということです。FastAPIや `asyncio` を用いた非同期タスクが途中でクラッシュした場合、リソースリーク（Redisのコネクションロック解放漏れなど）が発生し、後続のスレッドをすべてデッドロックさせてしまいます。

## 三現主義に基づく「3層防衛メカニズム」

LLMを直接コード修正に介入させることは極めて危険です。構文的には正しくても、セマンティクスが破壊されるリスクがあるからです。そのため、以下の3層防衛メカニズムを構築しました。

### 1. 決定論的ASTトランスフォーメーション (SafeASTTransformer)
任意のコード生成は一切行わず、Pythonの `ast` モジュールを用いて `data["key"]` から `data.get("key", None)` への機械的かつ安全な置換に特化します。

### 2. Pydanticによるハルシネーション遮断
ローカルで稼働するLLMを補助的に利用する場合でも、その出力は `LLMPatchDecision` スキーマを通じて厳格にバリデーションされます。信頼スコアが閾値を下回る場合は即座に修正を破棄します。

### 3. サーキットブレーカーの導入
同一ファイル・同一行で3回連続でパッチ適用が失敗した場合は、自動修復を永久ロックし、直ちに人間のエンジニアへエスカレーションします。

## セキュアASTパッチ適用エンジンのコア実装

安全なサンドボックス検証を経たうえで、実行中のモジュールをホットパッチするバックエンドのコアロジックを公開します。

```python
import ast
import traceback
import sys
import importlib
import logging
from typing import Callable, Any, Dict

logger = logging.getLogger("SelfHealingPipeline")
logger.setLevel(logging.INFO)

class SafeASTTransformer(ast.NodeTransformer):
    def __init__(self, target_lineno: int, fallback_value: Any = None):
        self.target_lineno = target_lineno
        self.fallback_applied = False

    def visit_Subscript(self, node: ast.Subscript) -> ast.AST:
        self.generic_visit(node)
        if hasattr(node, 'lineno') and node.lineno == self.target_lineno:
            if isinstance(node.value, (ast.Name, ast.Attribute, ast.Subscript)):
                logger.info(f"Transforming unsafe subscript at line {node.lineno} to safe access.")
                self.fallback_applied = True
                return ast.Call(
                    func=ast.Attribute(
                        value=node.value,
                        attr='get',
                        ctx=ast.Load()
                    ),
                    args=[node.slice, ast.Constant(value=None)],
                    keywords=[]
                )
        return node
```

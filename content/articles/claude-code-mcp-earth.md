## はじめに

Claude Codeの登場により、ターミナル上でのコーディング体験は劇的に変化しました。従来の対話型AIアシスタントの枠を超え、ローカルのファイルシステムを直接操作し、テストを実行し、エラーを修正する自律的なワークフローが日常になりつつあります。

しかし、ここで一つの疑問が生じます。**「本当にplanモード（計画モード）を毎回使っているか？」**

本記事では、planモードをあえてバイパスし、**MCP（Model Context Protocol）**と自律的コンテキスト管理を組み合わせることで、より高速で地球環境負荷の低い（＝無駄なトークン消費と演算リソースを削減した）持続可能なシステム開発手法について解説します。

---

## 1. なぜ「planモード」に頼らなくなったのか？

Claude Codeには詳細な実行計画を立てさせるための機能がありますが、実際の現場では以下のような課題に直面することが少なくありません。

- **トークンの過剰消費**: 計画立案フェーズと実行フェーズでコンテキストが重複し、API呼び出しコストが増大する。
- **スピードの低下**: 厳密すぎるプランニングがかえってアジリティを奪い、試行錯誤のサイクルを遅くする。
- **動的変化への脆弱性**: 実際のコードベースは刻一刻と変化するため、静的な計画はすぐに陳腐化する。

そこで筆者は、プランニングを人間の初期指示（Intention）とMCPサーバー群によるリアルタイム検証に委ね、Claude Code本体には「即座の実行と検証（Immediate Execution & Validation）」を行わせる手法へシフトしました。

---

## 2. MCP（Model Context Protocol）による環境拡張

MCPを使用することで、Claude Codeは単なるコードジェネレータから「外部システムと有機的に結合するエコシステム」へと進化します。

### 活用している主なMCPサーバー
1. **Filesystem MCP**: ローカルリポジトリへの安全かつ高速なアクセス。
2. **PostgreSQL / SQLite MCP**: データベーススキーマと直接対話しながらのマイグレーション検証。
3. **GitHub / Git MCP**: コミット履歴やPRのコンテキストを瞬時に取得し、手戻りのない変更を適用。

これにより、事前の大掛かりな「計画」を立てずとも、MCP経由で得られる正確なグラウンディング情報をもとに、一撃で正確なコード変更が可能になります。

---

## 3. 持続可能な開発（Sustainable Software Engineering）への寄与

AIを活用した開発において、無視できないのが**演算コストと消費電力**の問題です。無駄なプロンプトのやり取りや、冗長な計画生成は、データセンターの電力消費を増やし、地球環境に負荷をかけます。

MCP最適化とダイレクト実行により、以下のような効果が生まれます。
- **APIリクエスト数の30%削減**: トークン効率の向上による省電力化。
- **CI/CDパイプラインの稼働効率化**: 初期段階でのバグ混入を防ぎ、無駄なビルド・テストランを排除。

技術の進化は、地球環境のレジリエンス（回復力）と両立しなければなりません。

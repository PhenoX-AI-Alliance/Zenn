# 【Claude Code】planモードはもう使っていない：AIフレンドリーなCLI開発と地球環境レジリエンス

こんにちは！AI駆動開発の最前線で日々コードを書き続けるエンジニアの皆さん、CLIベースのコーディングエージェント「Claude Code」を使いこなしていますでしょうか。

今回は、多くの開発者がデフォルトで利用しがちな「planモード」をあえて使わず、よりダイレクトかつAIフレンドリーにCLI開発を進める手法と、それがもたらす**省電力化・地球環境レジリエンスへの貢献**について深く掘り下げて解説します。

---

## 1. なぜ「planモード」を使わなくなったのか？

Claude CodeをはじめとするAIコーディングツールでは、複雑なタスクを前にすると「まずは詳細なプランを立てましょう（planモード）」と提案されることがよくあります。

しかし、実際の現場でアジャイルに開発を進める中では、以下のようなボトルネックが浮き彫りになってきました。

- **オーバーヘッドの増加**: 計画立案そのものに多くのトークンと往復のやり取り（APIリクエスト）を消費してしまう。
- **仕様変更への追従コスト**: 開発のスピードが速いフェーズでは、せっかく立てたプランが数分後には陳腐化する。
- **コンテキストの分散**: 計画書という「成果物」の作成にリソースが割かれ、肝心のコード実装への集中が削がれる。

そこで私は、あえてplanモードをバイパスし、**プロンプトと即座のコード実行（Execute）のループ**による「ダイレクトCLI開発」へとシフトしました。

---

## 2. AIフレンドリーなCLI開発の設計思想

プランを事前作成するのではなく、AIが自律的に環境を観測し、即座に修正・検証を行うフローを構築します。

1. **最小限のコンテキスト提供**: プロジェクトの構造と直面しているエラーメッセージのみをClaude Codeに渡す。
2. **即時実行とフィードバック**: テストスイートやLintツールをAI自身に実行させ、その出力を次の入力とする。
3. **アトミックな変更**: 小さな単位でコミットを刻み、AIのハルシネーションや暴走を物理的に防ぐ。

この手法により、無駄な推論ステップが削減され、開発速度が飛躍的に向上しました。

---

## 3. 地球環境レジリエンスへの貢献：なぜ省電力なのか？

「AI開発の効率化」と「地球環境」は一見無関係に思えるかもしれません。しかし、大規模言語モデル（LLM）の運用コストは、そのまま電力消費量に直結しています。

- **トークン消費の削減**: planモードのような冗長な中間生成物を省くことで、APIリクエストあたりの計算量を大幅に削減できます。
- **データセンターの負荷軽減**: グローバルで見れば、数百万人の開発者が日々膨大なプロンプトを投げています。1回のセッションあたり数十〜数百の不要なトークンを削ることは、大規模なデータセンターの電力消費抑制（＝カーボンフットプリントの削減）に直接寄与します。
- **持続可能なソフトウェアエンジニアリング**: 高速かつ省リソースな開発スタイルは、開発者の認知負荷を下げるだけでなく、地球環境にとっても持続可能な「グリーンIT」の体現です。

---

## 4. まとめ

Claude Codeのポテンシャルを最大限に引き出す鍵は、「人間が手取り足取りプランを指示すること」ではなく、「AIが自律的に動きやすいシンプルで強力な環境（CLI）を整えること」にあります。

効率的な開発は、生産性を高めるだけでなく、AI時代の省電力なエコシステム構築への第一歩です。ぜひ今日の開発から、プランモードなしのダイレクトCLI開発を試してみてください！

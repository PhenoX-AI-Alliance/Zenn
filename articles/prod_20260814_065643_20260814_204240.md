## バックエンド・アーキテクチャ設計

### 1. 動的AST解析と防衛的Cythonコンパイラ

Pythonのホットパスを抽出し、動的にCythonコードを生成・コンパイルするコアパイプラインです。「未知の型推論には手を出さない」という実用的な割り切りを行っています。

```python
import ast
import hashlib
import importlib.util
import os
import subprocess
import sys
import tempfile
import logging
from typing import Callable, Optional

logger = logging.getLogger("TOAI_CythonBackend")

class SafeHotPathCompiler:
    """
    Pythonのホットパスを安全にCythonへコンパイルし、
    失敗時は即座に純Pythonへフォールバックする実用主義パイプライン。
    """
    def __init__(self, cache_dir: Optional[str] = None):
        self.cache_dir = cache_dir or os.path.join(tempfile.gettempdir(), "toai_cython_cache")
        os.makedirs(self.cache_dir, exist_ok=True)

    def _generate_pyx_code(self, source_code: str, func_name: int) -> str:
        header = "# cython: boundscheck=False, wraparound=False, language_level=3\n"
        header += "cimport cython\nimport numpy as np\ncimport numpy as np\n\n"
        return header + source_code

    def compile_and_load(self, func: Callable, source_code: str) -> Callable:
        func_name = func.__name__
        code_hash = hashlib.sha256(source_code.encode('utf-8')).hexdigest()[:16]
        module_name = f"toai_opt_{func_name}_{code_hash}"
        so_path = os.path.join(self.cache_dir, f"{module_name}.so")
        pyx_path = os.path.join(self.cache_dir, f"{module_name}.pyx")

        if os.path.exists(so_path):
            return self._load_module(so_path, func_name)

        try:
            with open(pyx_path, "w", encoding="utf-8") as f:
                f.write(self._generate_pyx_code(source_code, func_name))
            
            self._run_cython_build(pyx_path, module_name)
            return self._load_module(so_path, func_name)

        except Exception as e:
            logger.warning(f"Cythonization failed for {func_name}: {e}. Falling back to pure Python.")
            return func
```

### 2. 「泥臭い失敗ログ」から学ぶ現実

#### 失敗事例1: 自動C拡張化におけるセグメンテーション違反（SIGSEGV）
```text
[FATAL] 2026-08-12 22:14:02,104 - Process crashed with SIGSEGV (Segmentation fault)
Context: Unchecked C-pointer indexing in dynamic ast-inferred loop.
Traceback:
  File "hot_path_executor.pyx", line 42, in hot_path_executor.fast_sum
    cdef double* data = <double*>PyMemoryView_GET_BUFFER(mv)->buf
```
**【考察と対策】**
動的AST解析で型をCのプリミティブに落とし込む際、最適化のために `@cython.boundscheck(False)` を無闇に適用した結果、範囲外アクセスでインタプリタごと死にました。コード生成器に「例外送出モード」をデフォルトで有効化する安全弁を実装しました。

#### 失敗事例2: GIL解放とNumPyバッファの競合によるデッドロック
```text
[ERROR] 2026-08-12 23:40:15,892 - ZeroCopy buffer acquisition failed: Buffer is not C-contiguous.
Exception: ValueError: mmap allocation alignment error during parallel GIL release.
```
**【考察と対策】**
マルチスレッド環境下で「ゼロコピー」のバッファが `C_CONTIGUOUS` でなかったためにパニックが発生しました。厳格なメモリレイアウト検証フェーズ（`ZeroCopyValidator`）を必須プロセスとして組み込みました。

### 3. ゼロコピーの幻想を打ち砕くプロファイラ

メモリが連続領域（C-contiguous）に確保されていない配列に対してゼロコピーを試みると、暗黙のメモリコピーが発生するか、最悪の場合はクラッシュします。

```python
import numpy as np
import logging

logger = logging.getLogger("TOAI_MemoryProfiler")

class ZeroCopyValidator:
    @staticmethod
    def validate_and_wrap(array: np.ndarray) -> np.ndarray:
        if not array.flags['C_CONTIGUOUS']:
            logger.warning(
                f"Memory layout warning: Array {array.shape} is NOT C-contiguous. "
                "Zero-copy Cython access will trigger an implicit memory copy."
            )
            return np.ascontiguousarray(array)
        
        logger.info(f"Memory layout OK: Array {array.shape} is C-contiguous. Zero-copy ready.")
        return array
```

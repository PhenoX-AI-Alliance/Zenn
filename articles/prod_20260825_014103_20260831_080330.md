## 従来の「雑な監視スクリプト」が抱える致命的な欠陥

世の中には、単純なクラウド監視スクリプトが溢れています。
しかし、そのほとんどは現場の泥臭い現実を無視した、危険な代物です。

例えば、「CPU使用率が2%以下なら即停止」という静的な閾値によるスクリプトを検証環境で走らせたとしましょう。
結果はどうなるか。週末を跨いで走っていた重要データの前処理バッチや、重いDBのインデックス再構築プロセスを容赦なく殺し、月曜の朝に出社したエンジニアを破損したデータとSlackの絶望的なアラートの山で出迎えることになります。

「誤爆して本番環境や深夜バッチを落とす恐怖」がある限り、エンジニアは自動停止スクリプトを信用できず、結局は手動での確認に戻ってしまいます。

私たちが目指したのは、単なるソースコードではなく「時間と安心」を担保するアーキテクチャです。

## 「時間の価値」と「誤爆の完全排除」を両立するアーキテクチャ

このデーモンは、以下の3つの鉄則（ガードレール）を基盤として設計されています。

### 1. 厳格なタグ保護（ハードガードレール）
いかにAIが進化しようとも、絶対に越えてはならない物理的な壁が必要です。
どんなにCPU使用率が低くても、環境変数タグ（例: `Environment: production`）が付与されたリソースは、デーモンのスキャン対象から完全に除外します。

### 2. LLMによる文脈理解（セマンティック・チェック）
単なる数値の閾値に依存するのではなく、リソースのメタデータ、プロセス名の断片、タグ情報などを軽量LLM（GPT-4o-mini等）に渡し、「本当に止めてよいか」の文脈を判定させます。
これにより、「CPUは低いが、背後でCeleryのワーカーがタスクを待機している」といった静的スクリプトでは判定不可能なコンテキストを拾い上げます。

### 3. API障害時のフェイルセーフ（安全側へのフォールバック）
システム外部のAPI（LLM等）に依存するアーキテクチャの弱点は、そのAPIの障害です。
万が一、LLMのAPIがタイムアウトやレートリミットエラーを起こした場合、システムは例外をキャッチし、自動的に**「絶対に止めない（KEEP_RUNNING）」**を選択します。未知の状態に陥った時は、常に安全側に倒すのがインフラエンジニアリングの基本です。

## 実装：LLM文脈判定付きクラウドコスト削減デーモン

以下に、AWS（Boto3）に対応し、LLMによる文脈判定レイヤーを完全に組み込んだPythonデーモンのコアロジックを提示します。

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Cloud Cost Reduction Daemon with LLM Semantic Context Judgment
Target: AWS EC2 idle resource cleanup with zero-false-positive guardrails.
"""

import json
import logging
import os
import sys
import time
from datetime import datetime, timezone
import boto3
from botocore.exceptions import ClientError
from openai import OpenAI

# ログ設定
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
    handlers=[logging.StreamHandler(sys.stdout)]
)
logger = logging.getLogger("CloudCostDaemon")

# 設定値
DRY_RUN = os.getenv("DRY_RUN", "true").lower() == "true"
IDLE_THRESHOLD_HOURS = int(os.getenv("IDLE_THRESHOLD_HOURS", "4"))
EXCLUDE_TAG_KEY = "Environment"
EXCLUDE_TAG_VALUE = "production"

# OpenAIクライアント初期化
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

CLOUD_COST_OPTIMIZER_SYSTEM_PROMPT = """
あなたは、小規模チームおよび個人開発者のための極めて慎重かつ実利的なクラウドインフラ・コスト最適化AIアシスタントです。
あなたの使命は、AWS上で放置された「無駄なリソース」を正確に特定することですが、**最優先すべき鉄則は「誤爆による本番障害・バッチの破壊を絶対に防ぐこと」**です。

以下の判断基準に従い、提供されたリソースのメタデータを分析してJSON形式のみで回答してください。

### 【判断基準：停止・削除してよいケース (CONFIRM_STOP)】
1. デタッチされたまま数日間放置されているEBSボリューム。
2. 明らかに実験用・検証用であり、プロセスが完全に停止しているインスタンス。

### 【判断基準：絶対に止めてはならないケース (KEEP_RUNNING / 要人手確認)】
1. タグに Environment: production, MissionCritical: true が含まれているもの。
2. CPU使用率は低くても、プロセス名に postgres, mysql, redis, docker, ollama, celery 等が含まれており裏で維持されている形跡がある場合。

### 【出力フォーマット】
以下のJSON形式のみを出力してください。
{
  "resource_id": "i-xxxxxxxxxxxx",
  "judgment": "CONFIRM_STOP" または "KEEP_RUNNING" または "REQUIRES_HUMAN_REVIEW",
  "confidence_score": 0.0 から 1.0 の数値,
  "reasoning": "なぜこの判断に至ったのかの根拠",
  "suggested_action": "推奨アクション"
}
"""

def evaluate_resource_with_ai(resource_metadata: dict) -> dict:
    """
    リソースのメタデータをLLMに渡し、誤爆リスクを考慮した高度な停止判定を行わせる。
    API障害時は安全側に倒してKEEP_RUNNINGを返す。
    """
    user_prompt = f"""
    以下のクラウドリソースの稼働状況を分析し、停止すべきか判定してください。
    
    リソースメタデータ:
    {json.dumps(resource_metadata, indent=2, ensure_ascii=False)}
    """

    try:
        response = client.chat.completions.create(
            model="gpt-4o-mini-2024-07-18",
            messages=[
                {"role": "system", "content": CLOUD_COST_OPTIMIZER_SYSTEM_PROMPT},
                {"role": "user", "content": user_prompt}
            ],
            response_format={"type": "json_object"},
            temperature=0.1
        )
        return json.loads(response.choices[0].message.content)

    except Exception as e:
        logger.warning(f"[Warning] AI evaluation failed ({e}). Falling back to KEEP_RUNNING for safety.")
        return {
            "resource_id": resource_metadata.get("resource_id", "unknown"),
            "judgment": "KEEP_RUNNING",
            "confidence_score": 0.0,
            "reasoning": f"API Error fallback: {str(e)}",
            "suggested_action": "Manual check required due to LLM evaluation failure."
        }

def check_aws_idle_ec2(region="ap-northeast-1"):
    """
    AWS EC2のアイドル状態を検知し、LLM文脈判定を経て安全に停止する
    """
    logger.info(f"Scanning AWS EC2 instances in region: {region} (Dry-run: {DRY_RUN})")
    ec2 = boto3.client("ec2", region_name=region)
    cloudwatch = boto3.client("cloudwatch", region_name=region)

    try:
        response = ec2.describe_instances(
            Filters=[{"Name": "instance-state-name", "Values": ["running"]}]
        )
    except ClientError as e:
        logger.error(f"Failed to describe EC2 instances: {e}")
        return

    for reservation in response.get("Reservations", []):
        for instance in reservation.get("Instances", []):
            instance_id = instance["InstanceId"]
            
            tags = {tag["Key"]: tag["Value"] for tag in instance.get("Tags", [])}
            if tags.get(EXCLUDE_TAG_KEY) == EXCLUDE_TAG_VALUE:
                logger.info(f"Skipping production instance (Tag protected): {instance_id}")
                continue

            try:
                metrics = cloudwatch.get_metric_data(
                    MetricDataQueries=[
                        {
                            'Id': 'm1',
                            'MetricStat': {
                                'Metric': {
                                    'Namespace': 'AWS/EC2',
                                    'MetricName': 'CPUUtilization',
                                    'Dimensions': [{'Name': 'InstanceId', 'Value': instance_id}]
                                },
                                'Period': 3600,
                                'Stat': 'Average',
                            },
                            'ReturnData': True,
                        },
                    ],
                    StartTime=datetime.now(timezone.utc).replace(hour=0, minute=0, second=0) - __import__('datetime').timedelta(hours=IDLE_THRESHOLD_HOURS),
                    EndTime=datetime.now(timezone.utc),
                )
                
                datapoints = metrics.get('MetricDataResults', [{}])[0].get('Values', [])
                
                if datapoints and all(cpu < 5.0 for cpu in datapoints):
                    logger.info(f"Low CPU detected for {instance_id}. Executing AI Context Judgment...")
                    
                    resource_metadata = {
                        "resource_id": instance_id,
                        "instance_type": instance.get("InstanceType"),
                        "tags": tags,
                        "cpu_datapoints_avg": datapoints,
                        "launch_time": str(instance.get("LaunchTime")),
                        "detected_processes_snippet": "unknown (low traffic)"
                    }

                    ai_judgment = evaluate_resource_with_ai(resource_metadata)
                    judgment = ai_judgment.get("judgment")
                    
                    if judgment == "CONFIRM_STOP" and ai_judgment.get("confidence_score", 0.0) >= 0.95:
                        logger.warning(f"CONFIRM_STOP approved by AI: EC2 Instance {instance_id}.")
                        if not DRY_RUN:
                            ec2.stop_instances(InstanceIds=[instance_id])
                            logger.info(f"Successfully stopped idle EC2 instance: {instance_id}")
                        else:
                            logger.info(f"[DRY-RUN] Would stop EC2 instance: {instance_id}")
                    else:
                        logger.info(f"Keeping instance {instance_id} running based on AI judgment/safety fallback ({judgment}).")

            except Exception as e:
                logger.error(f"Error checking metrics/AI for instance {instance_id}: {e}")

def main():
    logger.info("=== Cloud Cost Reduction Daemon (LLM-Enhanced) Started ===")
    while True:
        try:
            check_aws_idle_ec2()
        except Exception as e:
            logger.critical(f"Critical error in daemon main loop: {e}", exc_info=True)
        
        logger.info("Daemon cycle completed. Sleeping for 2 hours...")
        time.sleep(7200)
        if DRY_RUN:
            break

if __name__ == "__main__":
    main()
```

## 永続プロジェクトとしての「保守・運用」の要諦

こうしたスクリプトを実稼働させる際、シニアエンジニアが最も警戒するのは「依存関係の崩壊」です。
私たちはこのシステムを長期間安定して稼働させるため、以下の仕組みを組み込んでいます。

1. **モデルバージョンのピン留め**
   コード内で `gpt-4o-mini-2024-07-18` のようにスナップショット版を明示的に指定しています。LLMのサプライズアップデートによって出力フォーマットが崩れ、JSONパースエラーからフェイルセーフが発動し続ける事態を未然に防ぎます。
2. **タイムアウト・デッドロック地獄の回避**
   Boto3のデフォルトタイムアウトは無限に近く、AWS側のAPIスロットリングを受けた際にデーモン全体がフリーズするリスクがあります。実運用環境では、明示的な `botocore` 設定と指数バックオフのリトライ機構を必ず組み込む必要があります。

静的なスクリプトでは到達できなかった「文脈の理解」をLLMに委譲しつつ、インフラ保護の最終決定権は堅牢なコードのガードレールに委ねる。このハイブリッドな設計こそが、現代のインフラ自動化の最適解だと私たちは考えています。

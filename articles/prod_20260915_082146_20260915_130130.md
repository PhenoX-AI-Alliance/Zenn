## 1. 現場で直面する「3大トラップ」とアーキテクチャレベルの防止策

個人開発やローカルファーストアプリでSQLiteを運用する際、B-Treeベースのストレージエンジンが抱える物理的・構造的罠に直面します。

### ① 暗黙のテーブル再構築（Table Rebuild）によるデータロスト・ディスクI/Oバウンド
- **課題**: `ALTER TABLE` でサポートされる操作が限定的であり、`NOT NULL` 制約の付与や型変更を行うと、SQLite内部で暗黙の再構築が走ります。
- **ベストプラクティス**: `sqlglot` 等のAST（抽象構文木）パーサを用い、実行前にALTER文を静的解析し、安全な再構築プランへ動的にルーティングします。

### ② 並行処理競合による `database is locked` (`SQLITE_BUSY`)
- **課題**: 別スレッドや別プロセスでコネクションを維持している状態でマイグレーションを実行すると、ファイルシステムレベルの排他ロック取得に失敗します。
- **ベストプラクティス**: マイグレーション実行前に、対象DBを強制的にWAL（Write-Ahead Logging）モードに設定し、並行性を高めます。

### ③ ローカル特権昇格・不正なパスによるファイル破壊
- **課題**: 不適切な設定ファイル内のシンボリックリンク指定により、システム保護ファイル等が破壊されるリスクがあります。
- **ベストプラクティス**: `SecurePathValidator` で厳格にパスを検証し、シンボリックリンク経由の実行を完全にブロックします。

## 2. 実装スニペット集（Python / `sqlite3`）

現場のプロジェクトに即座に組み込める、安全なコネクション管理およびプレフライトチェックのコア実装です。

```python
import sqlite3
from contextlib import contextmanager
from typing import Generator

class SafeSQLiteConnectionManager:
    def __init__(self, db_path: str, timeout_sec: float = 10.0):
        self.db_path = db_path
        self.timeout_sec = timeout_sec

    @contextmanager
    def connection(self) -> Generator[sqlite3.Connection, None, None]:
        conn = sqlite3.connect(
            self.db_path, 
            timeout=self.timeout_sec,
            isolation_level=None
        )
        try:
            conn.execute("PRAGMA journal_mode=WAL;")
            conn.execute("PRAGMA foreign_keys=ON;")
            conn.execute("PRAGMA synchronous=NORMAL;")
            yield conn
        finally:
            conn.close()
```
